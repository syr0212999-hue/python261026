# Todo List 웹사이트 TRD

## 1. 기술 범위

- HTML5: 문서 구조와 시맨틱 요소
- CSS3: 레이아웃, 반응형 스타일, 상태 UI
- JavaScript(ES6 이상): 상태 관리, 이벤트 처리, DOM 조작
- 브라우저 Web Storage API: `localStorage` 기반 데이터 저장

외부 프레임워크, UI 라이브러리 및 백엔드 서버는 사용하지 않는다.

## 2. 권장 파일 구조

```text
todolist/
├── index.html
├── css/
│   └── style.css
├── js/
│   └── app.js
├── prd.md
├── trd.md
└── task.md
```

## 3. 데이터 구조

각 할 일 항목은 다음 형태의 객체로 관리한다.

```javascript
{
  id: "고유 문자열 또는 숫자 ID",
  text: "할 일 내용",
  completed: false,
  createdAt: "ISO 형식 생성 시간"
}
```

전체 목록은 배열로 관리하며, JSON 문자열로 변환하여 `localStorage`에 저장한다.

## 4. 저장소 정의

- 저장소 키: `todoItems`
- 저장 방식: JSON
- 저장 시점: 항목 추가, 완료 상태 변경, 항목 삭제가 성공한 후
- 읽기 시점: 애플리케이션 초기화 시

## 5. 주요 처리 흐름

### 초기화

1. 저장된 할 일을 불러온다.
2. 저장 데이터가 없으면 빈 배열로 시작한다.
3. 저장 데이터 형식이 손상되었으면 빈 배열로 복구하고 오류를 피한다.
4. 초기 화면과 목록을 렌더링한다.

### 추가

1. 입력값 앞뒤 공백을 제거한다.
2. 빈 값이면 등록하지 않는다.
3. 새 항목 객체를 목록에 추가한다.
4. 목록을 저장하고 화면을 다시 렌더링한다.
5. 입력창을 초기화하고 포커스를 유지한다.

### 상태 변경

1. 이벤트로 선택된 항목 ID를 확인한다.
2. 해당 항목의 `completed` 값을 반대로 변경한다.
3. 목록을 저장하고 화면을 다시 렌더링한다.

### 삭제

1. 선택된 항목 ID를 확인한다.
2. 해당 항목을 배열에서 제거한다.
3. 목록을 저장하고 화면을 다시 렌더링한다.

## 6. DOM 및 접근성 요구사항

- 할 일 입력창에는 연결된 `<label>` 또는 명확한 `aria-label`을 제공한다.
- 체크박스는 키보드로 조작 가능해야 한다.
- 삭제 및 필터 버튼에는 접근 가능한 이름을 제공한다.
- 동적 상태 변경 후 포커스가 비정상적으로 사라지지 않도록 한다.

## 7. 반응형 기준

- 768px 이하: 입력 영역과 버튼을 세로 또는 폭 100% 구조로 배치한다.
- 480px 이하: 목록 항목의 버튼 간격과 텍스트 줄바꿈을 최적화한다.
- 고정 가로 폭보다 유연한 컨테이너 폭을 사용한다.

## 8. 검증 항목

- 빈 입력 등록 방지
- Enter 키와 추가 버튼 동작
- 완료 상태 변경 및 취소선 표시
- 전체/진행 중/완료됨 필터
- 새로고침 후 목록 유지
- 손상된 `localStorage` 데이터 처리
- 모바일 레이아웃 확인
